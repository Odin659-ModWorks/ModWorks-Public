# Research notes

The normal weapon builder is `FUN_710017f3a4`. It selects an eligible weapon/rank, calls `FUN_710017f224(..., 5)` for the weighted star roll, derives a skill-slot budget capped at eight, and passes that budget to `FUN_710017ea6c`.

The old v1.0.0 Better and Excellent cheats replaced the star-roll call and slot-budget calculation with constants. That forced exact values and unintentionally discarded higher natural rolls.

v1.1.0 left the weighted star roll intact and clamped its returned value upward only when it fell below the selected floor. v1.2.0 moves the star clamp to the shared `FUN_71002161f0` weapon-star setter, retaining its five-star ceiling while also covering static scenario-reward weapon construction through `FUN_71001fc3c4`. The generated-slot path still replays the original eight-slot cap before clamping the budget upward.

The helper code occupies the first 60 bytes of `FUN_710003fbac`, an 88-byte executable function with no external analyzed references and no raw absolute pointer occurrence in the source NSO. The two analyzed references within the region were internal branches belonging to the replaced function itself.

Static scenario reward records carry a predefined weapon identity/rank, star byte, and curated skill IDs. v1.2.0 raises their star floor but deliberately preserves their guaranteed identity/rank and skill layout. Randomly generated battlefield/result weapons continue through `FUN_710017f3a4`, where the rank and slot-floor patches apply.

Correction (2026-09-22): the old so-called rank-selection patches at `0x17F944` and `0x17F950` do not safely select a higher weapon tier. `w24` is the sum of five eligible-group weights, and the RNG result is walked across those groups. The old Excellent transform changes `random(total)` into `total - random(total/4)`, which can equal `total` when the random result is zero, outside the valid `[0,total)` range. Do not restore those two instructions. The actual group-to-weapon-ID mapping is through `FUN_7100214534`; table order alone has not been shown to correspond to quality.

On 2026-09-22, Excellent v1.3 repeatedly crashed Eden at battle start with an unmapped 16-bit write to address 0x14 (value 5). Substituting Perfect let the same battle load. Better/Excellent v1.3 both hook the shared star setter at executable offset 0x2161f0 and move its write to a helper at 0x3fbcc; the logged address and value are consistent with that write receiving a null pointer, though the original setter also writes at +0x14, so the log alone does not conclusively locate the faulting instruction. The v1.4 candidates reverted to the generated-drop star hook at 0x17fac8 and corrected the v1.1/v1.2 helper-address typo (the branch target was 0x3fbac but those cheats wrote the helper at 0x3fbbac). Excellent v1.4 still failed at battle start, with execution at unmapped 0x64. Inspection of 0x3fbac showed it is an actual function containing an indirect virtual call. It was never safe as a helper location despite lacking ordinary static references. Both v1.4 packages were archived out of Eden.

Excellent Floors v1.5.0 eliminates all branch hooks and borrowed code. In the seven-instruction shared star setter, it changes the returned result to 4 for original byte values 0-4 and 5 for values 5 or greater, preserving the five-star ceiling. The generated slot path is similarly changed to 7 for original values below 8 and 8 otherwise. Ghidra assembled the five changed instructions and they were checked for the expected byte-level clamp. Weapon-rank selection is deliberately left vanilla for the first in-game isolation test.

The slot patch changes the budget passed to `FUN_710017ea6c`, not a guarantee that every slot ends up with a unique non-empty skill. That function filters skills by unlock and eligibility conditions and can produce zero placeholders. Raising the filled-skill floor requires separate analysis. Static scenario rewards use curated weapon identity and skill layout, while the shared star setter covers their star byte.

Min 3 Stars, 6 Slots v1.5.0-rc1 takes a different inline route. At `0x17f258` and `0x17f260`, the weighted star roll's fallback and first tier are changed from 0 to 3. The existing result cap at `0x17f380`-`0x17f384` remains. This skips low-tier weights rather than clamping the result after the roll, so it changes distribution and does not cover fixed scenario rewards. The slot accessor `FUN_7100214d44` has one analyzed caller, `0x17fad4`; that caller passes a selected group index in `[0,4]`. The accessor's six instructions are rewritten to load the group's base slot count and return `max(base,6)`; the caller still adds its original bonuses and caps at eight. Removing the accessor's defensive out-of-range branch relies on that verified caller invariant. All seven altered instructions were assembled in Ghidra and restored in a read-only verification run. This version remains untested in game.
